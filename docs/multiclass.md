# Мультикласс

Правила — SRD 5.2.1, раздел «Multiclassing» (с. 24–25). Персонаж хранит классы списком
`classes: { classId, subclassId?, level, cantrips?, preparedSpells? }[]`. Первый в списке — стартовый класс.
Создание персонажа по-прежнему идёт с одного класса, второй класс берётся при повышении уровня.

## Решения, принятые с пользователем

1. **Приёмы оружия**: если их дают несколько классов, берётся наибольшее число, а не сумма. Только рукопашное оружие —
   если приёмы даёт лишь варвар.
2. **Две «Защиты без доспехов»** (варвар + монах): приложение само берёт ту, что даёт больший КЗ.
3. **Мистический рыцарь и Мистический ловкач** (подклассы PHB, «треть уровня» в ячейках) пока не учитываются: заклинаний
   у этих подклассов в приложении нет вообще. Делать отдельно.

## Этап А — расчёты (сделано, `a00f591`)

Код: `src/entities/character/model/` (`sheet.ts`, `spells.ts`, `build.ts`, `play.ts`, `rest.ts`).

- Бонус мастерства и рост заговоров — по общему уровню.
- Хиты: максимум кости только на 1-м уровне стартового класса, дальше среднее; кости хитов по каждому классу.
- Спасброски — только от стартового класса; владения второго класса — сокращённый список из `class.multiclass`.
- Умения — каждого класса по его уровню, подкласс у каждого класса свой.
- Ячейки (`characterSpellSlots`): один заклинатель — по своей таблице; несколько — по таблице мультикласса
  (все уровни барда, жреца, друида, чародея, волшебника + половина паладина и следопыта, вверх). Таблица мультикласса
  совпадает с таблицей волшебника и берётся из неё (`MULTICLASS_SLOTS_CLASS`).
- «Магия договора» колдуна при другом заклинателе — отдельные ячейки: `sheet.pactSlots`, `state.pactSlotsSpent`,
  `adjustPactSlot`; короткий отдых возвращает их, долгий — все. Колдун без других заклинателей — как одноклассовый
  (`spellcasting.slotsFromPact`).
- Заклинательство по классам: `sheet.spellcastingClasses` — у каждого класса своя характеристика, СЛ и бонус атаки.
- Заклинания по классам: у основного заклинателя (первого по порядку класса с заклинаниями) — в `cantrips` /
  `preparedSpells` персонажа, у остальных — в своей записи `classes[i]`. Функции `primaryCasterId`, `classSpellLists`,
  `setClassSpellLists`; лимиты `spellLimits(c, content, classId)` — как у одноклассового того же уровня.
- Книга волшебника работает и у волшебника-мультикласса.
- Тесты: `model/__tests__/multiclass.test.ts` («Ирма: плут 3 / волшебник 2», сочетания заклинателей, колдун).

## Этап Б — повышение уровня (сделано)

Код: `src/features/level-up/model/levelup.ts`, `src/pages/level-up/`, `src/features/edit-spells/`.

- Выбор, какой класс повышать: свой или новый (`startLevelUp(c, classId)`, `leveledClassId`).
- Требование 13+ в основной характеристике нового класса и всех текущих (`canMulticlassInto`), на экране — подпись
  «СИЛ 13 и ХАР 13» у недоступных классов (`multiclassRequirementText`).
- Новый класс: пояснение о сокращённых владениях; выбор навыка / инструмента (плут, следопыт, бард — ключи
  `mc.<класс>.prof.<n>`); умения 1-го уровня с выбором: стиль боя, «Божественный» / «Первобытный порядок»,
  компетентности и язык «Воровского жаргона», воззвание колдуна, приёмы оружия; хиты — среднее.
- Подкласс и заклинания — у повышаемого класса; окно выбора заклинаний (`SpellsEditSheet`) принимает `classId`.
  Новый волшебник — напоминание заполнить книгу из 6 заклинаний.
- Выборы уровня (черта за улучшение характеристик, стиль боя, навыки умений) помечаются **общим уровнем персонажа**,
  чтобы у «плут 4 / волшебник 4» они не перепутались. У одноклассовых общий уровень совпадает с уровнем класса,
  старые данные не меняются. Условия черт («4-й уровень+») — тоже по общему уровню.
- Кнопка на листе: «Повысить уровень: 5 → 6» — по общему уровню, предел 20.
- Тесты: `features/level-up/model/__tests__/multiclass-levelup.test.ts`.

## Этап В — интерфейс (осталось)

- **Название классов** «Плут 3 / Волшебник 2»: карточка в списке персонажей, шапка режима игры, лист на шаге 6, PDF.
- **Вкладка «Магия» по классам**: раздел каждого заклинателя со своей СЛ и бонусом атаки, его заговорами и
  подготовленными; кнопка «Изменить заклинания» у каждого класса (`SpellsEditSheet` с `classId`).
- **Ячейки договора отдельной строкой** на «Магии» и в PDF; «Сотворить» колдуна тратит ячейку договора.
- **PDF, страница заклинаний**: несколько заклинателей (характеристика, СЛ, атака у каждого), ячейки договора.

Кости хитов на коротком отдыхе уже тратятся по классам (к8 плута отдельно от к6 волшебника) — менять не нужно.

## Известные ограничения (не входят в этапы)

- «Дополнительная атака» от двух классов не складывается — приложение число атак не считает, только текст умений.
- При повышении уровня правило «заменить одно воззвание / вариант метамагии / подготовленное заклинание» не
  ограничивается: можно поменять сразу несколько.
- Мистический рыцарь / Мистический ловкач — см. решение 3.
- Опыт (XP) приложение не ведёт: уровень повышается кнопкой.
